## 발견
### confirmDeletion에서 await refreshLocalWorkingCopy() 직후 selectedProjectID 재검증 누락으로 인한 타 프로젝트 상태 오염
- 심각도: 중간
- 근거: Sources/SVNMac/ProjectStore+Deletion.swift:100-118
- 재현: 코드 기준 추정
- 트리거: 프로젝트 A에서 파일 삭제 확인 대화상자에서 확인을 누른 뒤, 비동기 refreshLocalWorkingCopy()가 진행되는 동안 사이드바에서 프로젝트 B로 전환한다.
- 증상: guard selectedProjectID == project.id 검증이 await 앞에만 있어, refresh 완료 후 프로젝트 B의 statuses와 selectedPaths에 프로젝트 A의 삭제 경로가 병합되고 프로젝트 B에 삭제 완료 알림이 뜬다.
- 확률: 낮음~중간. 삭제 대화상자 확인 직후 빠르게 프로젝트를 전환하는 타이밍에 발생.
- 고치는 방법: `await refreshLocalWorkingCopy()` 호출 직후 `guard selectedProjectID == project.id else { return }`를 추가한다.

### recoverWorkingCopy(to:) 실행 후 신규 등록된 프로젝트의 파일명 정규화(NFD) 검사 누락
- 심각도: 중간
- 근거: Sources/SVNMac/ProjectStore+Recovery.swift:77-87, Sources/SVNMac/ProjectStore.swift:1021-1045
- 재현: 코드 기준 추정
- 트리거: 유니코드 자소 분리 충돌로 "경로 복구"를 실행하여 NFD 분해 볼륨(외장 드라이브, 네트워크 공유 등)의 새 폴더로 작업 복사본을 복구한다.
- 증상: checkout, registerProjects, registerRecoveredCheckout, relocateProject와 달리 recoverWorkingCopy는 신규 등록된 recoveredProject에 대해 probeFilenameNormalization을 호출하지 않아, NFD 볼륨 경고 배너가 앱 재시작 전까지 표시되지 않는다.
- 확률: 중간. 경로 복구 자체가 NFD 충돌 해결 기능이며 복구 대상 대상 폴더 역시 NFD 볼륨일 가능성이 높다.
- 고치는 방법: `projects.append(recoveredProject)` 직후 `probeFilenameNormalization(for: recoveredProject)`를 호출한다.

### 파일 검색 중 트리 상태 갱신 시 WorkingCopyBrowserView의 검색 프로그레스 스피너 무한 고착
- 심각도: 중간
- 근거: Sources/SVNMac/ProjectStore+FileBrowser.swift:198-204, Sources/SVNMac/WorkingCopyBrowserView.swift:255-260
- 재현: 코드 기준 추정
- 트리거: 파일 브라우저 검색창에 검색어를 입력하여 비동기 검색이 시작된 상태에서 백그라운드 리프레시 등으로 `workingCopyBrowserTreeState.generation`이 변경된다.
- 증상: searchWorkingCopyFiles가 nil을 반환하고 WorkingCopyBrowserView.updateSearchResults의 guard 문에서 조기 반환되어 isSearching = false가 실행되지 않아, 검색창 아래에 ProgressView가 무한히 회전한다.
- 확률: 중간. 대규모 작업 복사본에서 타이핑 중 백그라운드 폴링 또는 윈도우 활성화 새로고침이 겹치면 발생.
- 고치는 방법: `WorkingCopyBrowserView.updateSearchResults` 내부를 `defer { isSearching = false }`로 감싸거나 guard 실패 시 `isSearching = false`를 지정한다.

### .alwaysLockAndOpen 정책 설정 시 타 사용자 잠금 파일이 경고 없이 쓰기 모드로 즉시 열림
- 심각도: 중간
- 근거: Sources/SVNMac/ProjectStore+Locking.swift:225-232
- 재현: 코드 기준 추정
- 트리거: 설정에서 문서 열기 동작을 "항상 잠그고 열기"로 선택한 상태에서 다른 사용자가 잠가 둔 파일을 파일 브라우저에서 더블 클릭한다.
- 증상: 사용자는 잠금 없이 열리는 것을 원하지 않아 해당 옵션을 켰으나, 앱이 openWithoutLock(request)을 자동 호출해 Excel/한글에서 즉시 편집 가능한 상태로 파일을 열어 향후 커밋 충돌을 유발한다.
- 확률: 높음. 잠금 필수 문서를 공유하는 팀에서 "항상 잠그고 열기"를 사용하는 기본 경로.
- 고치는 방법: `.alwaysLockAndOpen` 설정에서 타 사용자 잠금 발견 시 `openWithoutLock` 자동 호출 대신 확인 대화상자(`documentOpenRequest = request`)를 띄워 열기 여부를 묻는다.

### ForceUnlockRequest 및 BulkUnlockRequest의 projectID 누락으로 인한 프로젝트 격리 계약 불일치
- 심각도: 낮음
- 근거: Sources/SVNMac/ProjectStore+Locking.swift:13-17, Sources/SVNMac/LockWorkflow.swift:105-108
- 재현: 코드 기준 추정
- 트리거: 잠금 해제 실패로 강제 잠금 해제 확인창이 열린 상태에서 외부 이벤트나 단축키로 프로젝트가 전환된다.
- 증상: 다른 모든 요청 객체(DeletionRequest, DocumentOpenRequest, RevertRequest 등)와 달리 ForceUnlockRequest와 BulkUnlockRequest에 projectID 필드가 없어, 메서드 진입 시 요청-프로젝트 간 바인딩을 타입 수준에서 검증하지 않는다.
- 확률: 낮음. resetSelectedProjectState()에서 요청을 nil로 초기화하므로 실질 오작동 위험은 낮으나 아키텍처 계약 불일치.
- 고치는 방법: `ForceUnlockRequest` 및 `BulkUnlockRequest`에 `projectID: SVNProject.ID`를 추가하고 실행 전 `guard project.id == request.projectID`를 검증한다.

### BulkUnlockFailure에서 사용자 오류 알림 창에 Swift 디버그 설명자(String(describing:)) 노출
- 심각도: 낮음
- 근거: Sources/SVNMac/LockWorkflow.swift:140-143, Sources/SVNMac/RepositoryLocksView.swift:148-158
- 재현: 코드 기준 추정
- 트리거: 일괄 잠금 해제 실행 중 일부 파일에 대해 잠금 해제 실패가 발생한다.
- 증상: 실패 대화상자 본문에 `SVNError.commandFailed(exitCode: 1, stderr: "...")`와 같은 Swift 내부 enum 디버그 문자열이 사용자에게 그대로 노출된다.
- 확률: 중간. 일괄 잠금 해제 중 네트워크 문제나 타인 소유권 변경 시 발생.
- 고치는 방법: `BulkUnlockFailure` 생성 시 `String(describing: error)` 대신 `SVNErrorLocalization.message(for: error)` 또는 `localizedError(error)`를 적용한다.

### ProjectStore.isRelocatingProject의 operation.kind 패턴 매칭 누락으로 저장소 URL 이전 상태 미반영
- 심각도: 낮음
- 근거: Sources/SVNMac/ProjectStore.swift:530-535, Sources/SVNMac/ProjectStore+RepositoryMaintenance.swift:169, Sources/SVNMac/CredentialsView.swift:613
- 재현: 코드 기준 추정
- 트리거: 폴더 설정 화면에서 저장소 URL 변경(Relocate)을 실행한다.
- 증상: relocateSelectedRepository는 `.relocateRepository` 작업을 시작하지만 `isRelocatingProject`는 `.relocate`(로컬 폴더 경로 이전용)만 검사하므로, CredentialsView의 `isSaving` 프로그레스 인디케이터에 저장소 URL 이전 중 상태가 반영되지 않는다.
- 확률: 낮음. UI 진행 표시 일관성 결함.
- 고치는 방법: `isRelocatingProject`의 패턴 매칭에 `case .relocateRepository`를 추가한다.

## 블록 경계
- **WorkingCopyBrowserView $\leftrightarrow$ ProjectStore+FileBrowser.swift**: `searchWorkingCopyFiles`의 세대 번호 불일치 시 `nil` 반환 계약과 뷰의 `updateSearchResults` 간 에러/취소 처리 불일치로 `isSearching` 플래그가 해제되지 않고 무한 로딩 상태로 남음.
- **RepositoryLocksView $\leftrightarrow$ LockWorkflow.swift / ProjectStore+Locking.swift**: `BulkUnlockExecutor`가 반환하는 `BulkUnlockResult.failures`의 `message`가 지역화 문자열이 아닌 `String(describing:)` 원시 문자열로 전달되어 UI 알림 창에 개발자 디버그 포맷 노출.
- **CredentialsView $\leftrightarrow$ ProjectStore.swift / ProjectStore+RepositoryMaintenance.swift**: `CredentialsView`의 저장 중 상태 판별(`isSaving`)이 `store.isRelocatingProject`에 바인딩되어 있으나, 실제 저장소 URL 이전 작업은 `.relocateRepository`로 발행되어 상태 연동이 단절됨.
- **SVNCore.SVNClient $\leftrightarrow$ ProjectDependencies.swift**: `SVNClientServing` 프로토콜 기본 확장이 `workingCopyRepositoryURL`, `move`, `copy`, `relocate`, `setProperty`, `properties` 등을 `throw SVNError.invalidWorkingCopy`로 기본 구현하여, 새로운 Mock 또는 대리자 구현 시 미구현 메서드가 컴파일 단계에서 검출되지 않고 런타임에 실패함.
- **WorkingCopySplitBrowserView $\leftrightarrow$ ProjectStore+FileBrowser.swift**: 분할 브라우저의 디렉터리 캐시와 선택 상태(`WorkingCopySplitBrowserState`)가 뷰 내부 `@State`로 소유되어 있어, `ProjectStore`가 세대 번호(`workingCopyBrowserRefreshGeneration`)만으로 무효화를 제어함에 따라 뷰 비활성 시점의 프로젝트 전환 동기화가 SwiftUI 수명주기에 종속됨.

## 검증 공백
- **confirmDeletion 실행 중 프로젝트 전환 레이스**: `DeletionConfirmationTests` 및 `ProjectStoreTests`에 `confirmDeletion` 비동기 I/O 도중 `selectedProjectID`가 교체되는 시나리오 테스트 부재.
  - 필요한 테스트 입력: `client.scheduleDeletion` 지연 Mock 주입 후 `confirmDeletion` 호출과 동시에 `selectedProjectID` 변경 시 타 프로젝트 `selectedPaths` 오염 여부 검증.
- **recoverWorkingCopy(to:)의 probeFilenameNormalization 호출 여부**: `WorkingCopyRecoveryTests`에 복구 성공 후 신규 등록된 프로젝트의 볼륨 정규화 검사 수행 여부 검증 부재.
  - 필요한 테스트 입력: NFD 볼륨 경로로 복구 완료 후 `filenameNormalizationWarningProjectIDs` 포함 여부 검증.
- **searchWorkingCopyFiles 세대 번호 변경 시 뷰 상태**: `WorkingCopyBrowserModelTests`에 비동기 검색 도중 트리 `generation`이 변경되었을 때 뷰의 `isSearching` 해제 검증 부재.
  - 필요한 테스트 입력: `searchWorkingCopyFiles`가 `nil`을 반환하는 상황에서 `updateSearchResults()` 완료 후 `isSearching == false` 검증.
- **.alwaysLockAndOpen 정책 하 타인 소유 잠금 파일 열기**: `DocumentOpenConfirmationTests`에 `.alwaysLockAndOpen` 설정 상태에서 타인 잠금 문서 오픈 시 무단 열림 방지 검증 부재.
  - 필요한 테스트 입력: `existingLock.owner != username`인 파일에 대해 `.alwaysLockAndOpen` 정책으로 `prepareToOpen` 호출 시 확인 모달 표시 여부 검증.
- **BulkUnlockExecutor의 실패 메시지 지역화**: `LockWorkflowTests`에 일괄 해제 실패 시 `BulkUnlockFailure.message`가 사용자 표시용 문자열인지 검증 부재.
  - 필요한 테스트 입력: `unlock` 클로저가 `SVNError.commandFailed`를 던질 때 `failure.message`의 포맷 검증.

## 확인하지 않은 것
- **GUI 상호작용 및 시각적 애니메이션**: SwiftUI 뷰를 실제 렌더링 환경에서 구동하여 모달 시트 트랜지션 애니메이션 및 키보드 포커스 이동을 직접 확인하지 않음 (코드 정적 분석 및 CLI 환경 검증).
- **수만 파일 대규모 작업 복사본 I/O 부하 실측**: 수만 개 이상의 대규모 파일이 포함된 실제 SVN 작업 복사본에서 `searchWorkingCopyFiles`의 메모리 점유율 및 디스크 탐색 지연을 프로파일러로 실측하지 않음.
- **실제 네트워크 SVN 서버 인증서 만료 연동**: 로컬 `file://` 저장소 및 Mock 클라이언트 기반으로 검증하였으며, 사내 실제 Active Directory/LDAP 연동 SVN 서버 환경에서의 실시간 인증서 만료 처리는 직접 연결하지 않음.
