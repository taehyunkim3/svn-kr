# 누락된 추가 예약 자동 정리 설계

## 목표

`svn add` 이후 실제 파일 또는 폴더가 사라져 `missing`, revision `-1`로 남은 항목은 사용자가 커밋할 변경이 아니다. 안전성이 확인되는 경우 SVN 추가 예약 메타데이터를 자동으로 정리하고 변경 목록에서 숨긴다. 자동 정리할 수 없는 예외만 최상위 경로 한 줄로 표시한다.

## 자동 정리 조건

다음 조건을 모두 만족하는 최상위 누락 경로만 정리한다.

- 상태가 `missing`이고 revision이 없거나 `-1`이다.
- 해당 원문 경로에 실제 파일, 디렉터리 또는 심볼릭 링크가 없다.
- 정규화 기준으로 같은 NFC/NFD 로컬 경로나 unversioned 항목이 없다.
- 같은 경로 또는 하위에 충돌, 저장소에 존재하는 항목, 일반 수정·삭제 상태가 섞여 있지 않다.
- 하위 SVN 상태가 있다면 모두 아직 커밋되지 않은 추가 예약 계열이다.

후보는 가장 짧은 상위 경로로 접어 하위 파일마다 명령을 반복하지 않는다. 정리에는 원문 UTF-8 경로를 보존한 `svn revert --depth infinity`를 사용한다.

## 처리 흐름

1. 작업 복사본 상태를 읽고 안전한 정리 후보 루트를 계산한다.
2. 명령 실행 직전에 파일 시스템과 상태 조건을 다시 확인한다.
3. 후보 루트의 추가 예약을 revert한다.
4. 상태를 다시 읽어 후보와 하위 `missing`, revision `-1` 항목이 사라졌는지 확인한다.
5. 성공한 항목은 UI에 표시하지 않는다.
6. 명령 실패 또는 사후 검증 실패 시 사용자의 파일을 변경하지 않고, 해당 루트만 `정리 필요`로 표시한다.

## UI

- 정상 자동 정리: 아무 항목도 표시하지 않는다.
- 안전 조건 불충족 또는 정리 실패: 하위 항목을 모두 접고 최상위 경로 한 줄만 회색 `정리 필요` 배지로 표시한다.
- `충돌`, 실제 저장소 파일의 `로컬 누락`, NFC/NFD 대치 파일은 기존 전용 처리 흐름을 유지하며 자동 정리 대상에서 제외한다.

## 오류 및 안전성

- 새 파일을 만들거나 기존 파일을 삭제·덮어쓰지 않는다. SVN의 미완료 추가 예약만 해제한다.
- 경로가 다시 생겼거나 심볼릭 링크로 바뀌면 자동 정리를 중단한다.
- 원문 경로 전달이 불가능한 개행 또는 NUL 포함 경로는 정리하지 않고 예외로 표시한다.
- 하나의 후보 정리가 실패해도 다른 후보를 무조건 연속 처리하지 않는다. 상태를 다시 읽고 안전성을 재평가한다.

## 테스트

- 누락된 단일 추가 파일과 추가 디렉터리 트리를 최상위 한 번으로 정리한다.
- 실제 파일, 심볼릭 링크, NFC/NFD 동등 경로가 존재하면 정리하지 않는다.
- 충돌 또는 일반 버전 관리 상태가 섞이면 정리하지 않는다.
- revert 실패와 사후 상태 잔존 시 최상위 `정리 필요` 한 줄만 남긴다.
- 실제 SVN 작업 복사본에서 자동 정리 후 작업 복사본과 저장소 파일 내용이 변하지 않는지 확인한다.
