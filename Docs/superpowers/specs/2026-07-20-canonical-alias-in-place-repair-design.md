# SVN 정규화 동일 경로 제자리 복구 설계

## 문제

현재 앱은 NFC 서버 경로와 NFD 로컬 경로가 정규화 후 완전히 같아도 이를 `한글 경로 충돌`로 표시하고 새 작업 폴더 복구를 요구한다. 실제 로컬 변경이 없거나 실제 파일이 존재하는 경우에도 폴더 선택창이 나타난다.

실제 `svn-all` 작업 복사본에는 정상 관리 경로 `00 사업관리`와 정규화 동등한 NFD 경로 3개가 `missing`, `revision=-1`인 추가 예약으로 남아 있다. 이는 서로 다른 사용자 경로가 아니라 같은 논리 경로에 잘못 생성된 SVN 예약 메타데이터다.

## 경로 판정 원칙

- 전체 상대 경로를 NFC로 변환한 값이 완전히 같으면 같은 논리 경로로 판단한다.
- 같은 논리 경로에 SVN 서버가 관리하는 경로가 하나 있으면 그 정확한 원문 경로를 최종 경로로 사용한다.
- NFD 별칭 아래에 실제 파일이 존재해도 별도 경로나 충돌로 취급하지 않는다. 해당 파일 상태는 서버 관리 경로에 연결한다.
- SVN 서버 자체에 정규화 동등한 관리 경로가 둘 이상 존재해 기준 경로가 하나로 결정되지 않는 경우만 자동 정리하지 않는다.

## 안전한 제자리 정리

`SVNWorkingCopySnapshot`은 다음 조건을 모두 만족하는 항목을 `repairableAliasRoot`로 분류한다.

1. 상태가 `missing`이다.
2. 작업 복사본 리비전이 없거나 `-1`이어서 로컬 추가 예약임이 확인된다.
3. NFC 정규화 키가 기존의 유일한 서버 관리 경로와 같다.
4. 같은 조건의 하위 항목은 가장 짧은 상위 루트 하나로 축약한다.

정리 실행 직전에 최신 스냅샷으로 조건을 다시 확인한다. 조건이 유지되면 정확한 NFD 원문 루트 아래의 `revision=-1` 추가 예약 항목만 원문 UTF-8 바이트로 수집해 가장 깊은 경로부터 `svn revert --depth empty`로 되돌린다. `--remove-added`는 절대 사용하지 않으므로 실제 파일과 폴더는 삭제하지 않는다.

실제 SVN 1.14.5 재현에서 루트 `--depth infinity`는 정규화 동등한 하나의 물리 트리 아래 `scheduled.bin`뿐 아니라 NFC 관리 파일과 같은 물리 파일인 NFD `tracked.bin`까지 순회했다. 당시 파일 바이트는 유지됐지만 명령 범위가 사용자 변경 트리까지 확장되는 것이 확인되었으므로 채택하지 않는다. 반대로 `missing revision=-1` 항목만 `--depth empty`로 처리하면 실제 파일과 겹쳐 `added revision=-1`로 보이는 하위 예약이 남아 루트에서 `E155038`이 발생했다. 따라서 별칭 루트 아래의 `missing`/`added` `revision=-1` 예약 노드 전체를 deepest-first로 처리한다.

정리 후 스냅샷을 다시 읽어 다음을 검증한다.

- 정리 대상 추가 예약이 사라졌다.
- 정규화 동등한 실제 수정·신규 파일은 서버 관리 경로로 표시된다.
- 다른 실제 변경 상태와 사용자의 파일 내용은 유지된다.

검증이 실패하면 오류를 표시하고 커밋은 계속 차단한다.

## 화면 동작

- 충돌이 모두 제자리 정리 가능한 별칭이면 버튼을 `동일 한글 경로 정리`로 표시한다.
- 버튼을 누르면 폴더 선택창 없이 현재 작업 복사본의 잘못된 예약만 정리하고 즉시 새로고침한다.
- 실제 파일의 존재나 실제 수정 건수는 제자리 정리를 막는 조건이 아니다.
- 모호한 서버 경로가 하나라도 포함된 mixed 상태에서는 원클릭 정리를 표시하지 않는다.
- 서버에 정규화 동등한 관리 경로가 여러 개 있어 기준을 정할 수 없는 경우에는 자동 복구 동작 대신 서버 중복 경로를 수동으로 정리하라는 안내를 표시한다.

## 실제 로컬 경로와 커밋

제자리 정리는 Finder에 보이는 실제 파일·폴더 이름을 강제로 변경하지 않는다. macOS 파일시스템이 NFC/NFD 정규화 동등 이름을 같은 위치로 해석하는 특성을 사용하되, SVN 명령에는 서버가 관리하는 정확한 원문 경로를 전달한다.

커밋은 다음 순서로 처리한다.

1. 커밋 직전에 최신 작업 복사본 스냅샷을 다시 읽는다.
2. 제자리 정리 가능한 NFD 추가 예약이 남아 있으면 실제 파일을 보존한 채 예약 메타데이터를 먼저 정리한다.
3. 스냅샷을 다시 읽고 선택한 모든 경로를 유일한 서버 관리 경로에 매핑한다.
4. 기존 서버 상위 경로는 정확한 서버 원문을 사용하고, 실제 신규 경로 구성요소만 NFC로 만든다.
5. `svn add`, `svn delete`, `svn commit`의 모든 대상을 매핑된 경로로 전달한다.
6. add/delete 예약 또는 commit이 실패하면 이번 시도에서 만든 예약만 `svn revert`하고 원래 오류를 표시한다.
7. 커밋 성공 후 예약 롤백 `catch` 밖에서 상태를 다시 읽어 정규화 별칭이나 충돌이 새로 생성되지 않았는지 확인한다.
8. 저장소 성공 후 검증이 실패하면 완료 경고로 반환한다. 앱은 선택과 메시지를 완료 처리하고 새로고침하며, 서버 커밋을 되돌리거나 중복 재시도를 유도하지 않는다.

매핑 결과가 하나로 결정되지 않으면 어떤 add/delete도 실행하지 않고 커밋을 차단한다. 따라서 오류를 무시한 채 다른 한글 경로로 올라가는 동작은 허용하지 않는다.

## 테스트

- NFC 서버 경로와 NFD `missing revision=-1` 경로가 제자리 정리 대상으로 분류되는지 검증한다.
- 하위 예약 3개가 최상위 NFD 루트 하나로 축약되는지 검증한다.
- 실제 수정·신규 파일이 있어도 정리 가능하며 정리 뒤 서버 경로로 남는지 검증한다.
- 실제 macOS 로컬 저장소/작업 사본 fixture에서 deepest-first `--depth empty` 대상, `--remove-added` 부재, 수정·미추적 바이너리의 정확한 바이트와 실제 상태 보존을 검증한다.
- 실행 직전 상태가 달라지거나 서버 관리 경로가 둘 이상이면 어떤 revert도 실행하지 않는지 검증한다.
- 정리 성공 시 폴더 선택 시트가 열리지 않고 상태가 새로고침되는지 검증한다.
- 실제 수정 파일과 신규 파일을 함께 커밋해도 add와 commit 대상이 서버 원문 경로인지 검증한다.
- 커밋 성공 후 재검사에서 정규화 별칭이 발견되면 롤백하지 않고 완료 경고로 처리하는지 검증한다.
