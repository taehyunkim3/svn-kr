# 메인 창 활성화 시 로컬 변경 자동 갱신 설계

## 목표

SVN Mac의 메인 창이 key window가 될 때마다 선택된 작업 폴더의 변경 사항과 파일 목록을 한 번 갱신한다. 다른 앱에서 돌아오는 경우뿐 아니라 설정 등 앱 내부의 다른 창에서 메인 창으로 돌아오는 경우도 포함한다.

## 범위

- 메인 창에만 연결되는 AppKit 창 활성화 감지기를 둔다.
- 활성화 이벤트 한 번당 로컬 작업 복사본 상태와 파일 목록을 각각 한 번 갱신한다.
- 데모 모드, 선택 프로젝트 없음, 다른 작업 진행 중에는 자동 갱신을 시작하지 않는다.
- 상단 새로고침 버튼과 프로젝트 선택 변경은 기존처럼 로컬 상태, 파일 목록, 서버 커밋 기록을 모두 갱신한다.
- 자동 갱신에서는 서버 로그와 원격 업데이트 여부를 조회하지 않아 창 전환만으로 네트워크 요청이나 인증 화면이 발생하지 않게 한다.

## 구조

`ContentView` 배경에 AppKit의 실제 호스트 창을 추적하는 작은 `NSViewRepresentable`을 추가한다. 감지기는 자신이 붙은 창의 `NSWindow.didBecomeKeyNotification`만 구독하고, 창이 바뀌거나 뷰가 해제되면 기존 구독을 정리한다.

`ProjectStore.refresh()`의 로컬 스냅샷 적용 구간을 로컬 전용 메서드로 분리한다. 전체 새로고침은 이 메서드를 호출한 뒤 기존 원격 로그와 업데이트 여부 조회를 이어간다. `refreshForMainWindowActivation()`은 로컬 전용 메서드와 로컬 파일 트리 조회만 병렬로 실행한다. 서버 잠금 정보까지 함께 조회하는 `refreshWorkingCopyBrowser()`는 자동 활성화 경로에서 사용하지 않는다. 로컬 전용 갱신은 기존 원격 업데이트 여부와 경로 복구 상태를 보존한다.

## 동작과 오류 처리

창 활성화 콜백은 현재 선택 프로젝트를 기준으로 실행한다. 진행 중인 작업이 있으면 중복 실행하지 않는다. 기존 요청 ID 검증을 유지해 갱신 도중 프로젝트가 바뀌어도 이전 결과가 새 프로젝트 상태를 덮어쓰지 않게 한다. 로컬 갱신 오류는 기존 오류 표시 경로를 사용한다.

## 검증

- 창 감지기가 대상 창의 key 활성화만 전달하고 창 교체 시 구독을 정리하는지 검증한다.
- 자동 활성화 갱신이 로컬 상태와 파일 목록만 호출하고 원격 로그 조회를 하지 않는지 검증한다.
- 수동 전체 새로고침과 프로젝트 선택 변경의 기존 동작이 유지되는지 검증한다.
- 저장소 전체 `swift test`를 실행한다.
