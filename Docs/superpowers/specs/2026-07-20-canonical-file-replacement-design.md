# 정규화 별칭 파일 대치 상태 설계

## 문제

macOS에서 서버가 관리하는 NFC 파일을 Finder 등의 `파일 대치`로 덮어쓰면 실제 디렉터리 항목이 NFD 이름으로 다시 만들어질 수 있다. SVN 1.14.5는 이를 NFC 관리 파일의 `missing`과 정규화 동등한 NFD 파일의 `unversioned` 두 항목으로 보고한다. 현재 스냅샷은 NFD 항목을 제거하고 NFC `missing`만 남겨 실제 대치 파일을 `로컬 누락`으로 표시한다.

## 목표 동작

- 하나의 관리 파일 `missing revision>=0`과 하나의 정규화 동등한 미추적 일반 파일이 대응하면 대치 후보로 본다.
- SVN `BASE` 바이트와 로컬 바이트가 다르면 관리 경로의 `수정`으로 표시한다.
- 바이트가 같으면 변경 목록에서 제외한다.
- 실제 대응 파일이 없거나 디렉터리, 심볼릭 링크, 다중 별칭, 다중 관리 경로처럼 안전하게 하나로 결정할 수 없는 경우 기존 상태 또는 충돌을 유지한다.
- `missing revision=-1` 추가 예약 별칭 정리와 실제 삭제 상태는 기존 의미를 유지한다.

## 구조

`SVNWorkingCopySnapshot`은 XML만으로 식별 가능한 원문 관리 경로와 미추적 별칭 경로의 일대일 대치 후보를 보존한다. `SVNClient.workingCopySnapshot`은 파일 시스템과 `svn cat --revision BASE`에 접근할 수 있으므로 후보의 바이트를 비교하고 표시 상태를 `modified` 또는 정상으로 해석한다. BASE 출력은 임시 파일로 받고 로컬 파일과 청크 단위로 비교해 HWP 같은 바이너리와 큰 파일을 문자열 변환이나 전체 메모리 적재 없이 처리한다.

선택 커밋 전에는 수정으로 판정된 대치 파일을 권한이 제한된 임시 디렉터리에 복사하고 바이트 일치를 검증한다. 그 다음 관리 경로를 `svn revert`로 복원하고 백업을 청크 단위로 다시 쓴다. 백업은 상태가 실제 `modified`인지 재검증할 때까지 유지한다. 어느 단계에서든 실패하면 원래 별칭 경로로 복원하며, 복원까지 실패하면 남아 있는 백업 경로를 오류에 명시한다.

Foundation이 SVN 경로 인자를 NFD로 바꾸지 않도록 원문 UTF-8 경로는 임시 인자 파일에서 고정 셸 래퍼가 읽어 `exec`에 전달한다. `@`가 있는 경로는 SVN peg escape를 붙이고, 줄바꿈이 있는 경로는 줄 단위 전달에서 다른 대상으로 해석될 수 있으므로 변경 명령 전에 명시적으로 거부한다.

## 상태 조합

- `missing 관리 파일 + unversioned 별칭 일반 파일`, 다른 바이트: `modified`
- 같은 조합, 동일 바이트: 변경 없음
- `modified 관리 파일 + unversioned 별칭`: 기존 `modified` 우선
- `missing 관리 파일`만 존재: `missing`
- `missing revision=-1 + unversioned`: 기존 추가 예약 별칭 처리
- 여러 관리 원문 또는 여러 미추적 별칭: 자동 대치 판정 금지
- 일반 파일이 아닌 디렉터리나 심볼릭 링크: 자동 대치 판정 금지

## 검증

가짜 SVN 테스트로 다른/동일 바이너리 판정, 모호한 조합 제외, 디스크 백업 존재, 실패 복원, peg escape와 줄바꿈 거부를 검증한다. Case-sensitive APFS와 실제 `svnadmin` 통합 fixture로 대치 파일이 `modified`로 표시되고 선택 커밋 후 저장소 내용이 대치 바이트와 일치하는지 확인한다. 마지막으로 전체 `swift test`를 실행한다.
