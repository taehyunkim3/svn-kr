# 커밋 기록 로딩 상태 표시 설계

## 목표

서버 커밋 기록을 불러오는 동안 빈 결과나 커밋 미선택 안내를 표시하지 않고, 목록과 상세 패널 각각에 로딩 스피너와 `커밋 기록 불러오는 중…` 안내를 표시한다. 로딩 완료 후 실제 기록이 없을 때만 `커밋 기록 없음`을 표시한다.

## 선택한 접근

현재 `WorkspaceSplitView` 구조를 유지하고, 기록 관련 작업이 실행 중인지 판별하는 상태를 `ProjectStore`가 제공한다. `HistoryView`는 이 상태와 `logs.isEmpty`를 조합해 목록 패널의 로딩/빈 상태를 선택하고, `HistoryRevisionDiffView`는 같은 조건으로 상세 패널의 로딩/선택 안내를 선택한다.

전체 분할 뷰에 적용된 빈 상태 오버레이는 목록 패널 내부의 고정 컨테이너로 이동한다. 따라서 안내 문구가 좌우 분할선 가운데에 걸리지 않고 목록 패널 중앙에만 배치된다. 상세 패널은 기존 고정 컨테이너와 `overlay` 전환 구조를 유지한다.

## 상태 규칙

- 선택 프로젝트의 `.refresh` 또는 `.refreshHistory` 작업이 실행 중이면 커밋 기록 로딩 중으로 판단한다.
- 로딩 중이고 `logs`가 비어 있으면 양쪽 패널에 스피너와 로딩 문구를 표시한다.
- 로딩 중이어도 기존 `logs`가 있으면 목록을 유지한다.
- 로딩이 끝난 뒤 `logs`가 비어 있으면 목록 패널에만 `커밋 기록 없음`을 표시한다.
- 기록이 있고 선택된 커밋이 없으면 상세 패널에 기존 `커밋을 선택하세요` 안내를 표시한다.
- `이전 기록 50개 더 불러오기`는 초기 빈 로딩 상태에서는 표시하지 않는다.

## 레이아웃 제약

- 창과 패널 크기 숫자는 추가하지 않는다.
- `WorkspaceSplitView`를 유지하고 중첩 SplitView를 만들지 않는다.
- 로딩, 빈 결과, 선택 안내가 바뀌어도 각 패널의 바깥 컨테이너 타입과 크기를 유지한다.
- 상태 안내는 각 패널 내부 컨테이너의 `overlay`로 표시한다.

## 검증

- 기록 작업 종류에 따른 로딩 상태 판별 테스트를 먼저 추가한다.
- `swift test`로 기능 및 레이아웃 회귀를 확인한다.
- Git diff에서 관련 Store, 기록 화면, 테스트, 문서만 변경되었는지 확인한다.
