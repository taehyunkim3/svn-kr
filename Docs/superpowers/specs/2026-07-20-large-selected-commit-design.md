# 대량 선택 커밋 안정화 설계

## 배경

현재 선택 커밋은 선택 경로마다 전체 상태 배열을 다시 검색하고, 추가·삭제 예약 명령을 경로별로 실행한 뒤 모든 경로를 최종 `svn commit` 명령행 인자로 전달한다. 변경 항목이 수만 개이면 메인 스레드의 이차 시간 검색, 과도한 하위 프로세스 생성, macOS 명령행 인자 길이 제한 때문에 앱이 멈추거나 커밋 시작에 실패할 수 있다.

## 목표

- 수만 개 변경 항목에서도 커밋 버튼을 누른 직후 UI가 장시간 멈추지 않는다.
- 한 번의 선택 커밋은 하나의 SVN 리비전으로 남는다.
- 사용자가 선택한 경로만 커밋하는 기존 의미를 유지한다.
- 상위 폴더와 그 하위 경로가 함께 선택돼도 중복 SVN 작업을 하지 않는다.
- 경로 개수와 전체 바이트 수가 운영체제 명령행 인자 제한에 영향을 받지 않는다.

## 설계

### 선택 검증

`ProjectStore`는 전체 상태 배열을 선택 경로마다 검색하지 않는다. 충돌 상태 경로를 한 번 `Set`으로 만들고 선택 경로 집합과 교집합을 검사한다. 처리량은 선택 수와 상태 수에 선형으로 비례한다.

### 커밋 대상 정규화

`SVNClient`는 현재 상태를 경로별 사전으로 변환한다. 선택 경로는 정렬한 뒤 이미 선택된 상위 디렉터리가 포함하는 하위 경로를 제거한다. SVN의 디렉터리 대상은 재귀적으로 처리되므로 최종 커밋 의미는 유지하면서 중복 인자와 중복 add/delete 예약을 없앤다.

경로 구분은 문자열 접두사만 사용하지 않고 `/` 경계를 확인한다. 예를 들어 `Sources/App`은 `Sources/Application`의 상위 경로로 취급하지 않는다.

### SVN 명령 실행

정규화한 경로를 UTF-8 임시 대상 파일에 한 줄씩 기록하고 SVN의 전역 `--targets` 옵션으로 전달한다. 최종 커밋은 한 번만 실행하므로 하나의 SVN 리비전을 유지한다.

추가 대상과 삭제 대상도 각각 모아 별도 임시 대상 파일을 사용한 단일 `svn add --parents` 및 `svn delete --force` 명령으로 예약한다. 대상이 없으면 해당 명령을 실행하지 않는다. 임시 파일은 명령 성공·실패와 관계없이 삭제한다.

대상 파일 안의 각 경로는 현재 작업 복사본 기준 상대 경로다. 기존 자격 증명, UTF-8 로케일, 인증서 처리 경로는 변경하지 않는다.

## 오류 처리

- 대상 파일 생성 실패는 기존 커밋 오류 흐름으로 전달한다.
- add/delete/commit 중 하나라도 실패하면 후속 명령을 실행하지 않고 SVN 오류를 사용자에게 표시한다.
- 최종 커밋 성공 전에는 선택 상태와 커밋 메시지를 비우지 않는다.

## 테스트

- 상위 폴더와 하위 파일을 함께 선택하면 최상위 대상만 남는지 검증한다.
- 비슷한 접두사를 가진 형제 경로가 잘못 제거되지 않는지 검증한다.
- 대량 경로 커밋이 개별 경로 인자가 아니라 `--targets` 파일을 사용하고 한 번의 commit으로 끝나는지 가짜 SVN 실행 파일로 검증한다.
- 추가 및 삭제 대상이 각각 한 번의 배치 명령으로 실행되는지 검증한다.
- 기존 한글 메시지, 자격 증명, 선택 커밋 테스트를 포함한 전체 `swift test`를 실행한다.

## 범위 제외

- 커밋을 여러 리비전으로 나누는 청크 커밋
- 변경 목록 UI의 가상화 또는 레이아웃 변경
- SVN 서버 설정이나 작업 복사본 자체의 변경
