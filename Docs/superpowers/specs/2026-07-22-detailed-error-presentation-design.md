# 상세 오류 표시 설계

## 목적

앱의 모든 오류가 짧은 기본 알림에 잘리거나 현재 열린 시트 뒤에 가려지지 않도록 한다. 사용자는 SVN 명령의 원문을 포함한 전체 오류 내용을 스크롤해서 읽고, 지원 요청이나 진단을 위해 한 번에 복사할 수 있어야 한다.

## 범위

- SVN 명령, 파일 열기, Keychain, 충돌 해결, 작업 폴더 복구 등 `ProjectStore.errorMessage`로 전달되는 모든 오류에 공통 표시를 적용한다.
- 체크아웃 시트와 복구 시트처럼 자체 오류 영역이 있는 화면도 동일한 상세 오류 표현과 복사 동작을 사용한다.
- 오류 이력 저장, 파일 내보내기, 서버 전송은 포함하지 않는다.
- 기존 오류 문자열에 없는 명령 인자나 인증 정보를 새로 수집하거나 노출하지 않는다.

## 사용자 경험

오류가 발생하면 현재 사용자가 보고 있는 화면에서 상세 오류가 표시된다. 화면에는 다음 요소가 있다.

- 현지화된 `오류` 제목
- 전체 오류 원문을 표시하는 고정폭 텍스트 영역
- 내용이 영역을 넘을 때 사용할 수 있는 세로 및 가로 스크롤
- 전체 오류 문자열을 클립보드에 넣는 `오류 내용 복사` 버튼
- 오류 상태를 비우고 화면을 닫는 `닫기` 버튼
- 복사 직후 버튼 또는 보조 문구로 제공하는 짧은 복사 완료 피드백

짧은 오류도 같은 컴포넌트를 사용한다. 오류 텍스트는 선택할 수 있으며, 긴 경로나 SVN stderr의 줄바꿈을 임의로 삭제하지 않는다.

## 구조

### 오류 데이터

`ProjectStore.errorMessage: String?`를 단일 오류 상태로 유지한다. `SVNError.commandFailed`와 `localizedError`가 제공하는 명령명 및 stderr 원문도 그대로 전달한다. 이번 변경에서 별도의 영구 로그 모델은 만들지 않는다.

### 공통 표시 컴포넌트

재사용 가능한 상세 오류 뷰를 추가한다. 이 뷰는 오류 문자열, 언어, 복사 동작, 닫기 동작을 입력으로 받고 화면 배치만 담당한다. 클립보드 쓰기는 작은 별도 동작으로 분리해 전체 문자열이 손실 없이 전달되는지 테스트할 수 있게 한다.

일반 작업 화면에서는 기존 루트 `alert`를 상세 오류 표현으로 교체한다. 별도 시트가 떠 있는 동안 발생하는 오류는 그 시트의 화면 계층에서 같은 공통 컴포넌트를 사용해 루트 화면 뒤에 가려지지 않게 한다. 체크아웃 진행 로그는 기존 진행 내용을 유지하고, 오류 원문 영역에 공통 복사 동작을 제공한다.

### 레이아웃

상세 오류 영역의 최소·기본 크기 값은 `AppLayout.swift`에 둔다. 본문은 바깥 컨테이너 크기를 유지한 채 내부 스크롤 영역에서만 늘어난다. 기존 시트 최소 크기나 주요 창 크기는 변경하지 않는다.

## 상태 흐름

1. 기존 작업 코드가 오류를 잡아 `localizedError(error)` 또는 명시적 오류 문자열을 `errorMessage`에 저장한다.
2. 현재 화면의 상세 오류 표시기가 문자열 전체를 렌더링한다.
3. 사용자가 `오류 내용 복사`를 누르면 표시 중인 동일 문자열 전체가 클립보드에 기록되고 복사 완료 상태가 표시된다.
4. 사용자가 `닫기`를 누르면 `errorMessage`가 `nil`이 되고 복사 완료 상태도 초기화된다.

새 오류가 기존 오류를 대체하면 표시 내용과 복사 대상도 즉시 새 문자열로 바뀐다.

## 오류 및 보안 처리

- 복사 실패가 원래 오류를 덮어쓰지 않도록 한다.
- 오류 원문은 앱이 현재 받은 문자열까지만 표시한다. 비밀번호, Keychain 값, 표준입력 내용은 새로 결합하지 않는다.
- 줄 수나 글자 수로 오류 문자열을 자르지 않는다.
- 체크아웃처럼 이미 진행 로그가 있는 화면에서는 진행 로그와 오류 원문을 구분해 표시한다.

## 테스트 및 검증

- 긴 여러 줄 오류가 변경 없이 상세 오류 모델과 복사 대상으로 전달되는지 단위 테스트한다.
- 새 오류로 교체됐을 때 복사 대상이 갱신되는지 검증한다.
- 닫기 동작이 `errorMessage`와 화면 상태를 초기화하는지 검증한다.
- SVN 명령 실패의 명령명과 stderr 원문이 기존처럼 보존되는지 회귀 테스트한다.
- 소스 구조 테스트로 루트 기본 오류 `alert`가 공통 상세 오류 표시로 교체되고, 체크아웃·복구 화면이 공통 표현을 사용하는지 확인한다.
- `Docs/LayoutArchitecture.md`의 크기 규칙을 확인하고 전체 `swift test`를 실행한다.

## 완료 조건

- 앱에서 발생하는 오류를 현재 활성 화면에서 확인할 수 있다.
- 긴 오류는 잘리지 않고 스크롤할 수 있다.
- 사용자가 전체 오류 내용을 한 번에 복사할 수 있다.
- 기존 오류 원문과 체크아웃 진행 로그가 손실되지 않는다.
- 전체 테스트가 통과한다.
