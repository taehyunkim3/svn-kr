# 혼합 리비전 표시와 커밋 진행 상태 설계

## 배경

SVN 작업 복사본은 선택한 변경 항목을 모두 커밋한 뒤에도 혼합 리비전이 될 수 있다. 커밋된 항목은 새 리비전으로 이동하지만 변경되지 않은 루트와 다른 항목은 이전 기준 리비전을 유지한다. 현재 앱은 작업 복사본 루트의 단일 리비전만 `내 로컬 폴더` 값으로 표시해, 서버에서 내려받을 변경이 없는 최신 상태에서도 오래된 리비전처럼 보인다.

또한 커밋 작업 중 공통 툴바에만 스피너가 나타난다. 사용자가 누른 `선택 항목 커밋` 버튼에는 진행 상태가 없고, 공통 스피너는 인접 툴바 컨트롤의 시각적 경계 밖에 놓인다.

## 목표

- 작업 복사본이 혼합 리비전이면 최소·최대 리비전 범위를 정확히 표시한다.
- 서버에서 내려받을 변경이 없는지는 기존 최신 상태 판단과 분리해 유지한다.
- 커밋 중에는 실행 지점인 커밋 버튼 안에서 진행 상태를 보여 준다.
- 공통 툴바 스피너는 커밋 이외의 전역 작업에만 표시하고, 안정된 크기의 컨테이너 안에 배치한다.

## 작업 복사본 리비전 모델

SVN 클라이언트는 루트의 `svn info --show-item revision` 단일 값 대신 작업 복사본 전체 범위를 조회한다. 범위는 최소 리비전과 최대 리비전을 보존하는 값 모델로 표현한다.

- 단일 리비전: `r13295`
- 혼합 리비전: `r13292–r13295`
- 타임라인 위치: 작업 복사본에 실제 포함된 가장 높은 리비전인 `r13295`
- 혼합 상태 배지: 타임라인과 요약에서 이전 리비전 항목도 포함됨을 명시한다.

`최신` 표시는 리비전 문자열 비교로 결정하지 않는다. 기존 원격 상태 확인 결과가 `내려받을 변경 없음`일 때 계속 표시한다. 따라서 `r13292–r13295 · 최신`은 모순이 아니라 혼합 작업 복사본의 정확한 상태다.

SVN 명령 출력에 수정·전환 등 상태 접미사가 포함될 수 있으므로 파서는 숫자 범위만 추출하고, 해석할 수 없는 출력은 명시적 오류로 처리한다.

## 커밋 진행 상태

`ProjectStore.activeOperations`의 작업 종류를 이용해 현재 선택 프로젝트의 커밋 여부를 계산한다. 단순한 전역 `isWorking`과 구분해 다른 프로젝트 또는 다른 작업의 상태가 커밋 버튼에 잘못 나타나지 않게 한다.

커밋 중 버튼은 다음 상태를 유지한다.

- 작은 `ProgressView`
- `커밋 중…` 텍스트
- 기존 prominent 버튼 스타일과 클릭 영역
- 중복 실행 방지를 위한 비활성화

공통 툴바 스피너는 커밋 중에는 표시하지 않는다. 새로고침·업데이트처럼 별도 실행 버튼 내부에 진행 표시가 없는 전역 작업에서만 고정 크기 컨테이너 안에 표시해 툴바 경계를 벗어나 보이지 않게 한다.

## 오류와 완료 처리

커밋 성공·실패 및 인증 재개 흐름은 기존 동작을 유지한다. 성공 시 입력 메시지를 비우고 새로고침하며, 실패 시 버튼이 원래 상태로 돌아가 기존 오류 또는 인증 UI를 표시한다. 리비전 범위 조회 실패는 기존 새로고침 오류 처리 경로를 사용한다.

## 테스트

- 단일 리비전과 혼합 리비전 명령 출력 파싱
- 상태 접미사가 포함된 혼합 리비전 출력 파싱
- 혼합 리비전의 표시 문자열과 타임라인 기준 리비전
- 선택 프로젝트의 커밋 작업만 커밋 진행 상태로 판단
- 커밋 완료 후 새 범위가 새로고침 결과에 반영됨
- `swift test` 전체 회귀 검증
- `Docs/LayoutArchitecture.md`의 최소·기본·확대 창 및 변경 사항 탭 버튼 상태 확인

## 범위 밖

- 커밋 직후 자동 `svn update`로 작업 복사본을 단일 리비전으로 강제하지 않는다.
- 타임라인을 최소·최대 리비전 사이의 세로 범위 그래프로 확장하지 않는다.
- 기존 커밋·인증·오류 문구와 서버 최신 판단 알고리즘은 변경하지 않는다.
