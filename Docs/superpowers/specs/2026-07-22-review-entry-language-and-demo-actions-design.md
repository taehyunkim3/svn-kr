# 심사 진입 화면 언어 선택과 데모 동작 설계

## 목표

첫 실행의 저장소 추가 화면에서 설정 창을 열지 않고 앱 언어를 선택할 수 있게 한다. 심사용 샘플 프로젝트는 발견 가능하되 일반 사용자의 주 동작처럼 강조하지 않고, 데모에 진입한 뒤에는 종료 동작을 명확하게 표시한다.

## 언어 선택

- 저장소 추가 화면의 제목 영역 우측에 지구본 아이콘과 현재 UI 언어로 번역된 `언어` 또는 `Language` 메뉴 버튼을 둔다.
- 메뉴를 열면 현재 지원하는 `한국어`, `English`를 각 언어의 고유 표기로 보여 준다.
- 선택 값은 기존 `AppSettings.languageKey`의 `@AppStorage`에 저장하며 선택 즉시 시트와 앱 전체 환경에 반영한다.
- 언어 목록과 표시 이름은 `AppLanguage`가 소유한다. 이후 `日本語` 같은 언어를 추가할 때 화면 레이아웃이나 메뉴 코드를 다시 작성하지 않고 열거형 항목과 표시 이름만 확장할 수 있어야 한다.

## 샘플 프로젝트 진입

- `샘플 프로젝트 둘러보기` 또는 `Browse Sample Project`는 저장소 추가 화면 하단의 우측 동작 묶음에 둔다.
- 기본 `bordered` 스타일을 사용하고 별도 강조색이나 prominent 스타일은 적용하지 않는다.
- 취소와 체크아웃보다 앞에 배치해 심사자가 찾을 수는 있지만, 일반 사용자의 기본 체크아웃 동작과 시각적 우선순위를 경쟁하지 않게 한다.
- 진입 시 기존 `ProjectStore.demo()`를 사용하며 UserDefaults 프로젝트 데이터, Keychain, 로컬 폴더와 SVN 서버에는 접근하지 않는다.

## 데모 종료

- 데모 모드 툴바에는 아이콘만이 아니라 `데모 종료` 또는 `Exit Demo` 텍스트를 항상 표시한다.
- 종료 버튼은 주황색 `borderedProminent` 스타일로 표시해 새로고침·업데이트 버튼과 명확히 구분한다.
- 종료하면 기존 일반 저장소 상태로 돌아가며, 일반 모드에는 종료 버튼을 표시하지 않는다.

## 레이아웃과 상태

- 저장소 추가 시트의 기존 최소 크기와 바깥 컨테이너 구조는 유지한다.
- 제목 영역은 `HStack` 안에서 제목·설명을 왼쪽, 언어 메뉴를 오른쪽에 배치한다.
- 하단 버튼 수가 늘어도 시트 최소 너비 안에서 잘리지 않도록 기존 폴더 등록은 왼쪽, 샘플·취소·체크아웃은 오른쪽 묶음으로 구분한다.

## 회귀 검증

- 언어 메뉴가 `AppLanguage.allCases`를 사용하고 모든 언어가 고유 표시 이름을 제공하는지 테스트한다.
- 첫 실행 저장소 시트에 언어 메뉴와 비강조 샘플 버튼이 연결되어 있는지 확인한다.
- 데모 모드 종료 버튼이 현지화된 텍스트와 주황색 prominent 스타일을 사용하는지 확인한다.
- `swift test` 전체 실행과 최소·기본 창 크기에서 저장소 추가 시트의 버튼 잘림 여부를 확인한다.
