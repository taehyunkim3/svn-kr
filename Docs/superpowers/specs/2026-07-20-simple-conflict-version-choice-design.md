# 단순 충돌 버전 선택과 미추적 폴더 안내 설계

## 목표

충돌 해결 화면을 `내 파일`과 `서버 파일`을 각각 열어 보고 둘 중 하나를 최종 작업 파일로 고르는 흐름으로 단순화한다. 미추적 폴더는 한 행으로 유지하되, 선택하면 하위 파일이 함께 추가된다는 사실을 행 안에서 명확히 안내한다.

## 범위

### 포함

- 내 파일과 서버 파일이 모두 존재하는 파일 내용 충돌
- 텍스트와 HWP, PDF, XLSX, PPTX 등 바이너리 파일의 파일 전체 단위 선택
- 두 버전의 안전한 자동 백업과 기본 편집 프로그램으로 열기
- 선택한 버전으로 충돌 해결 후 상태 새로고침
- 미추적 폴더 행의 재귀 추가 안내

### 제외

- 줄, 문단, 셀 또는 슬라이드 단위 병합
- 편집한 제3의 파일을 최종본으로 가져오기
- 백업 여부를 정하는 체크박스
- 미추적 폴더의 하위 트리 펼치기와 하위 파일 개별 선택
- 폴더 이동·삭제, 로컬 추가와 서버 추가가 겹친 트리 충돌
- 속성 충돌

트리 충돌과 속성 충돌은 이 단순 선택 화면에서 자동 처리하지 않는다. 두 파일 중 하나를 고르는 의미가 성립하지 않으므로 기존 충돌 상태를 유지하고 지원하지 않는 충돌 유형임을 안내한다.

## 미추적 폴더 표시

미추적 폴더는 현재처럼 최상위 폴더 한 행만 표시하고 선택 단위도 폴더 전체로 유지한다. 폴더 행에는 다음 보조 문구를 표시한다.

> 하위 파일이 함께 추가됩니다.

일반 미추적 파일에는 이 문구를 표시하지 않는다. 앱은 파일 시스템에서 해당 경로가 실제 디렉터리인지 확인해 문구 표시 여부를 결정한다. 폴더를 선택해 커밋하면 현재 동작대로 `svn add`와 `svn commit`이 재귀적으로 하위 파일을 포함한다.

## 충돌 해결 화면

화면에는 같은 크기의 두 버전 영역만 둔다.

### 내 파일

- 경로, 수정 시각, 파일 크기를 표시한다.
- `내 파일 열기`로 비교용 복사본을 기본 편집 프로그램에서 연다.
- `내 파일 사용`을 선택할 수 있다.
- 선택 전 다음 내용을 확인한다.

> 내 파일을 유지합니다. 이후 커밋하면 서버 파일이 이 내용으로 변경됩니다.

### 서버 파일

- 서버 리비전과 파일 크기를 표시한다.
- `서버 파일 열기`로 비교용 복사본을 기본 편집 프로그램에서 연다.
- `서버 파일 사용`을 선택할 수 있다.
- 선택 전 다음 경고를 표시한다.

> 서버 파일로 교체합니다. 작업 중이던 내 변경 내용은 작업 폴더에서 사라집니다. 내 원본은 앱 백업 폴더에 보관됩니다.

화면 아래에는 `취소`만 둔다. 직접 병합이나 별도 해결 완료 버튼은 제공하지 않는다.

## 백업과 파일 열기

충돌 화면을 준비할 때 `ConflictFileService`가 내 파일과 서버 파일을 Application Support의 충돌 백업 폴더에 각각 복사한다. 백업은 사용자 선택 없이 항상 수행하며 한쪽 복사라도 실패하면 버전 선택 버튼을 활성화하지 않는다.

화면의 열기 버튼은 작업 파일이나 SVN 임시 파일을 직접 열지 않고 백업 복사본을 연다. 따라서 사용자가 비교 중 파일을 편집해도 실제 작업 파일과 SVN 충돌 보조 파일은 바뀌지 않는다. 두 복사본은 서로 다른 경로와 구분 가능한 파일명을 사용한다.

## 버전 선택 처리

1. 충돌 상세 정보와 두 원본 파일의 존재를 확인한다.
2. 두 버전을 안전한 백업 폴더에 복사한다.
3. 사용자가 두 복사본을 각각 열어 확인한다.
4. `내 파일 사용`은 `svn resolve --accept mine-full`을 실행한다.
5. `서버 파일 사용`은 `svn resolve --accept theirs-full`을 실행한다.
6. SVN 명령이 성공한 경우에만 화면을 닫고 상태를 새로고침한다.
7. 결과 파일은 커밋 전 변경 목록에서 다시 확인할 수 있으며, 서버 저장소는 사용자가 이후 커밋하기 전까지 변경되지 않는다.

명령 실패 시 충돌 화면과 백업을 유지하고 오류를 표시한다. 앱은 실패를 해결 완료로 간주하지 않는다.

## 바이너리 파일 동작

바이너리 파일도 텍스트 파일과 동일하게 파일 전체 단위로 처리한다. SVN Mac은 바이너리 내부의 충돌 구간을 분석하거나 병합하지 않는다. 사용자는 HWP, Word, Excel 등 기본 편집 프로그램에서 두 복사본을 각각 열어 육안으로 확인한 뒤 전체 버전 하나를 선택한다.

## 구조 경계

- `SVNCore`는 충돌 상세, 선택 가능한 충돌 유형, `mine-full`·`theirs-full` 실행을 담당한다.
- `ConflictFileService`는 두 비교용 백업을 원자적으로 준비하고 메타데이터를 반환한다.
- `ProjectStore`는 준비·열기·선택·새로고침 상태를 관리한다.
- `ConflictResolutionView`는 두 버전 표시와 전체 버전 선택만 담당한다.
- 미추적 폴더 여부는 코어의 작업 복사본 경로 검사 결과로 UI에 전달하며, 화면이 직접 재귀 탐색하지 않는다.

## 오류와 안전 조건

- 내 파일 또는 서버 파일이 없으면 선택 화면을 제공하지 않는다.
- 비교용 백업 생성에 실패하면 어떤 `svn resolve`도 실행하지 않는다.
- 심볼릭 링크와 실제 디렉터리를 구분하고 링크 대상은 재귀 탐색하지 않는다.
- 지원하지 않는 트리·속성 충돌은 자동 해결하지 않는다.
- 해결 실패 후 원본, SVN 보조 파일과 충돌 상태를 유지한다.
- 버전 선택 성공 후에도 자동 커밋하지 않는다.

## 검증

- 미추적 일반 파일에는 안내가 없고 미추적 폴더에만 재귀 포함 안내가 표시되는지 확인한다.
- 폴더 한 행을 선택한 실제 SVN 커밋이 하위 바이너리 파일을 포함하는 기존 통합 테스트를 유지한다.
- 충돌 준비 시 내 파일과 서버 파일 복사본이 모두 생성되는지 확인한다.
- 각 열기 동작이 작업 파일이 아닌 대응하는 백업 복사본을 여는지 확인한다.
- `내 파일 사용`이 `mine-full`, `서버 파일 사용`이 `theirs-full`을 정확히 전달하는지 확인한다.
- 백업 실패와 한쪽 버전 누락 시 resolve 명령이 실행되지 않는지 확인한다.
- resolve 실패 시 충돌 상태가 유지되고, 성공 시 새로고침되지만 자동 커밋되지 않는지 확인한다.
- 텍스트와 바이너리 fixture 모두 파일 전체 선택 결과 바이트가 선택한 버전과 같은지 확인한다.
- `swift test` 전체와 앱 패키징·코드 서명 검증을 실행한다.
