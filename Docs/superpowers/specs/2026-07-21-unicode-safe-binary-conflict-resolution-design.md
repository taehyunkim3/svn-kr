# 한글 경로 안전 바이너리 충돌 해결 설계

## 목표

macOS 파일 시스템이 표시하는 NFD 경로와 SVN 작업 사본이 관리하는 NFC 경로가 달라도 사용자가 일반 충돌과 동일하게 HWP 같은 바이너리 파일의 충돌을 해결할 수 있게 한다. 경로를 유일하게 확정할 수 없는 경우에는 추측하지 않고 기존 한글 경로 충돌 흐름으로 차단한다.

## 사용자 흐름

변경 목록에서 `충돌 해결…`을 선택하면 앱은 화면의 로컬 경로를 현재 작업 사본 스냅샷의 정확한 SVN 관리 경로로 변환한다. 유일한 관리 경로가 확인되면 충돌 해결 창을 바로 열고, 경로 표현을 보정한 경우에만 창 상단에 작은 안내를 표시한다.

충돌 해결 창은 다음 선택을 제공한다.

- `내 파일 사용`: 충돌 당시 사용자의 파일을 최종 작업 파일로 유지한다.
- `서버 파일 사용`: 업데이트로 받은 서버 파일을 최종 작업 파일로 사용한다.
- `현재 작업 파일 사용`: 사용자가 두 백업본을 확인하고 실제 작업 파일을 직접 편집한 결과를 유지한다.

세 선택 모두 실행 직전 작업 파일을 별도 복구본으로 보존한다. 충돌 해결은 커밋하지 않으며, 결과 파일은 사용자가 확인한 뒤 별도로 커밋한다.

## 경로 판정

단순히 모든 입력을 NFC로 변환하거나 NFC/NFD 명령을 차례로 재시도하지 않는다. `SVNWorkingCopySnapshot.versionedPathsByCanonicalKey`와 `resolvedPath(for:)`를 사용해 정규화 키에 대응하는 SVN 원문 경로를 찾는다.

- 정규화 기준 관리 노드가 하나이면 NFC 명령 경로를 먼저 `svn info`로 검증하고, macOS가 이미 정확한 원문을 보존한 경우를 위해 스냅샷 원문 경로를 다음 후보로 검증한다. 성공한 한 경로를 `svn resolve`까지 고정해서 사용한다.
- 관리 경로가 둘 이상이면 자동 선택하지 않고 한글 경로 충돌로 처리한다.
- 해결 세션에는 화면 표시 경로와 SVN 명령 경로를 분리해 저장한다.
- 후보 검증은 정규화 기준 관리 노드가 하나인 경우에만 수행하며, 조회에 성공한 경로와 resolve에 사용하는 경로는 반드시 동일하다.

## 충돌 파일 처리

기존 `ConflictFileService`의 백업과 원자적 복원 절차를 유지한다. 조회 단계에서 내 파일과 서버 파일을 앱 지원 폴더에 복사하고, 실제 해결 직전 현재 작업 파일을 숨김 복구본으로 다시 보존한다.

`현재 작업 파일 사용`은 `svn resolve --accept working`을 실행한다. 내 파일 또는 서버 파일 선택은 기존 `mine-full`과 `theirs-full`을 사용한다. 바이너리 충돌에서 SVN이 별도 mine 파일을 제공하지 않으면 세션 준비 시 보존한 mine 원본을 작업 파일에 복원한 뒤 resolve한다.

resolve 명령 성공 뒤 상태를 새로 읽고 대상이 더 이상 `conflicted`가 아닌지 검증한다. 검증에 실패하면 세션과 백업을 유지하고 완료 안내를 표시하지 않는다.

## UI 상태

- 경로가 자동 보정됐으면 충돌 창 상단에 비차단 안내를 표시한다.
- `.mine`, `.r숫자` 충돌 보조 파일은 정규화 동등 경로 기준으로 변경 목록에서 숨긴다.
- 해결 중에는 선택과 닫기를 비활성화한다.
- 성공하면 창을 닫고 `충돌을 해결했습니다. 파일을 확인한 뒤 커밋하세요.`를 표시한다.
- 실패하면 창을 유지하고 복구본 위치와 오류를 표시한다.
- 트리 충돌과 정규화 중복 경로는 자동 해결하지 않는다.

## 코드 경계

- `SVNWorkingCopySnapshot`: 화면 경로에서 유일한 SVN 관리 원문 경로를 판정한다.
- `ProjectStore+Conflicts`: 경로 판정, 세션 생성, resolve 후 상태 검증을 조정한다.
- `ConflictResolutionSession`: 표시 경로, 실제 관리 경로, 자동 보정 여부를 보존한다.
- `ConflictResolutionView`: 세 가지 해결 선택과 경로 보정 안내를 표시한다.
- `SVNXMLParser`: 충돌 보조 파일을 정규화 동등 경로 기준으로 숨기되 실제 관리 경로 충돌은 병합하지 않는다.

## 테스트

- NFD 화면 경로가 유일한 NFC 관리 경로로 변환되는 단위 테스트
- 정규화 동등 관리 경로가 둘 이상이면 자동 선택하지 않는 테스트
- 보정된 경로가 `svn info`와 `svn resolve`에 동일하게 전달되는 저장소 테스트
- 내 파일, 서버 파일, 현재 작업 파일 선택별 백업과 resolve 동작 테스트
- resolve 후 충돌이 남아 있으면 세션과 오류를 유지하는 테스트
- NFC/NFD가 섞인 `.mine`, `.r숫자` 파일 숨김 테스트
- 실제 로컬 SVN 저장소에서 바이너리 충돌을 생성해 해결하는 통합 테스트
- 전체 `swift test`

## 비범위

- HWP 내용의 자동 병합
- 트리 충돌 자동 해결
- 정규화하면 같은 서버 관리 경로가 둘 이상인 손상 상태의 자동 정리
- 충돌 해결 직후 자동 커밋
