# 되돌리기 확인 요청 경합 수정 설계

## 문제

변경 목록에서 `로컬 변경 되돌리기`를 확인하면 SwiftUI가 경고창을 닫으면서
`ProjectStore.revertRequest`를 `nil`로 만든다. 버튼 동작은 별도 `Task`에서
`confirmRevert()`를 호출하므로, Task가 시작되기 전에 요청이 지워지면 Store의
guard가 작업을 중단한다. 이 경우 `svn revert`가 실행되지 않아 전체 새로고침
후에도 파일이 변경 목록에 남는다.

## 설계

경고창의 `presenting` 클로저가 전달받은 `RevertRequest`를 버튼 동작에서 직접
캡처하고 `ProjectStore.confirmRevert(_:)`에 인자로 전달한다. Store 메서드는
가변 화면 상태인 `revertRequest`를 다시 읽지 않고, 전달받은 요청과 현재 선택된
프로젝트만으로 되돌리기를 수행한다.

경고창 표시 상태를 닫을 때 `revertRequest`를 비우는 현재 동작은 유지한다.
취소와 외부 닫기의 상태 정리 의미를 바꾸지 않으면서, 확인 동작만 화면 상태 정리와
독립시킨다.

## 상태 흐름

1. 사용자가 변경 파일의 되돌리기를 요청한다.
2. 경고창이 해당 `RevertRequest`를 표시한다.
3. 사용자가 확인하면 버튼이 표시 중인 요청을 값으로 캡처한다.
4. 경고창 종료 과정에서 Store의 `revertRequest`가 비워질 수 있다.
5. 캡처된 요청을 받은 Store가 정확한 상대 경로에 `svn revert`를 실행한다.
6. 성공하면 선택 상태를 제거하고 전체 상태를 새로고침한다.
7. 실패하면 기존과 같이 오류 메시지를 표시한다.

## 회귀 테스트

Store의 `revertRequest`가 이미 `nil`인 상태에서 명시적인 `RevertRequest`를
`confirmRevert(_:)`에 전달한다. 테스트용 SVN 클라이언트가 다음을 기록하도록 한다.

- `revert`가 정확히 한 번 호출되는지
- 선택된 프로젝트 경로와 요청 파일 상대 경로가 전달되는지
- 성공 후 새 작업 복사본 스냅샷이 반영되는지
- 되돌린 파일이 선택 목록에서 제거되는지

테스트를 먼저 실패시키고, 메서드 시그니처와 확인창 호출부만 최소 수정해 통과시킨다.
이 작업에는 레이아웃 변경이나 다른 파일 작업 흐름의 리팩터링을 포함하지 않는다.
