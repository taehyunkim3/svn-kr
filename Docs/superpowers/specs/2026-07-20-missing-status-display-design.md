# SVN 한글 경로 정규화, 누락 상태 및 안전 복구 설계

## 문제

변경 목록은 SVN의 `deleted`와 `missing`을 모두 `삭제`로 표시한다. 특히 새로 추가 예약된 경로가 디스크에서 사라지면 SVN은 `item="missing"`, `revision="-1"`을 반환하는데, 현재 화면은 이를 기존 저장소 폴더 삭제처럼 보여준다. 해당 행을 선택하면 커밋 직전에 자동 `svn delete --force` 대상으로도 처리되어 사용자가 의도하지 않은 삭제로 오해할 수 있다.

macOS SVN이 파일 시스템에서 읽은 한글 경로를 NFD 자모 분리 형태로 반환할 수 있다. 앱이 이 경로를 그대로 `svn add --parents`에 넘기면 저장소가 이미 관리하는 NFC 완성형 상위 경로 옆에 화면상 같은 NFD 추가 예약 트리가 생긴다. 이후 하나의 실제 변경이 수천 개의 `missing`과 `unversioned` 항목처럼 보이고, 실패한 커밋의 로컬 예약이 남을 수 있다.

## 경로 식별 정책

- 기존 SVN 관리 경로는 서버와 작업 복사본이 가진 정확한 원문을 보존한다.
- 경로 비교에는 NFC로 변환한 `canonicalKey`를 사용한다.
- 화면에는 NFC로 변환한 `displayPath`를 사용한다.
- 새 파일과 새 폴더의 이름은 NFC로 저장한다.
- 하나의 새 로컬 경로가 정확히 하나의 기존 SVN 경로와 정규화 동등하면 기존 SVN 경로에 자동 연결한다.
- 같은 `canonicalKey`에 둘 이상의 기존 SVN 경로 또는 서로 다른 로컬 내용이 연결되면 자동 결정하지 않고 충돌로 차단한다.

## 작업 복사본 스냅샷

한 번의 `svn status --verbose --no-ignore --xml` 결과에서 변경 상태, 정상 관리 경로, 작업 복사본 리비전 범위, 한글 경로 충돌을 함께 만든다. 기존의 변경 상태 조회와 리비전 조회가 같은 작업 복사본을 따로 순회하지 않게 한다.

스냅샷은 NFD 추가 예약 누락 트리와 NFC 정상 관리 트리가 정규화 동등한 경우 최상위 충돌 하나로 축약한다. 실제 `modified`, `added`, `unversioned`, `deleted` 항목은 정규화된 기존 상위 경로에 연결해 별도로 유지한다.

## 상태 표현

- `deleted`: `삭제` / `Deleted`를 유지한다.
- `missing`이며 `revision == "-1"`: `추가 취소됨` / `Addition Missing`으로 표시한다.
- 그 밖의 `missing`: `로컬 누락` / `Locally Missing`으로 표시한다.
- 추가 예약 누락은 중립적인 회색 배지를 사용하고, 실제 삭제와 일반 로컬 누락은 빨간색을 유지한다.

## 선택 및 커밋 안전성

`revision == "-1"`인 추가 예약 누락 항목은 변경 목록에서 체크박스를 표시하지 않고 커밋 대상으로 선택할 수 없게 한다. 새로고침할 때도 기존 선택 집합에서 해당 경로를 제거한다. 일반 `missing`은 기존처럼 사용자가 선택하면 삭제 예약 후 커밋할 수 있다.

커밋 직전에 새 스냅샷을 만들고 선택 경로를 저장소의 정확한 관리 상위 경로에 다시 매핑한다. 충돌이 있으면 어떤 로컬 예약도 만들기 전에 커밋을 중단한다. 새 경로는 NFC로 `svn add --parents`하고, 커밋 실패 시 앱이 이번 작업에서 만든 add/delete 예약만 revert하여 실제 파일은 보존한다.

## 충돌 표시

- 충돌 트리의 수천 개 하위 행은 표시하지 않는다.
- 최상위 경로마다 `한글 경로 충돌` 행과 영향 항목 수를 표시한다.
- 충돌이 있는 동안 일반 커밋 버튼은 비활성화한다.
- 실제 수정 및 신규 파일은 충돌 요약과 분리하여 정상 상태명으로 표시한다.

## 경로 자동 복구

앞으로 앱이 만든 예약은 작업 단위로 기록하므로 실패 시 같은 작업 안에서 자동 원상복구한다. 이미 출처를 알 수 없는 중복 예약이 존재하는 작업 복사본은 같은 폴더에서 직접 revert하거나 `.svn/wc.db`를 수정하지 않는다.

사용자가 `경로 자동 복구`를 실행하면 다음 절차를 수행한다.

1. 사용자가 선택한 빈 대상 폴더에 현재 작업 복사본과 같은 저장소 URL을 새로 체크아웃한다.
2. 원본 스냅샷에서 정규화 충돌로 생긴 가짜 `missing`과 기존 관리 경로와 겹치는 가짜 `unversioned`를 제외한다.
3. 실제 수정 파일과 실제 신규 파일을 서버의 정확한 관리 상위 경로 및 NFC 새 이름으로 복사한다.
4. 실제 삭제 상태는 새 작업 복사본에서도 누락 상태로 재현한다.
5. 새 작업 복사본의 SVN 상태를 다시 검사해 충돌이 없고 예상 변경만 남았는지 확인한다.
6. 검증 성공 후 복구 폴더를 새 프로젝트로 등록하고 선택한다. 원본 프로젝트와 원본 파일은 그대로 보존한다.

대상 폴더가 비어 있지 않거나, 정규화 키가 여러 서버 경로에 대응하거나, 파일 종류가 다르거나, 서로 다른 신규 파일이 같은 정규화 키를 사용하면 복구를 중단하고 충돌 경로를 안내한다.

## 구조

표시와 선택 가능 여부를 화면 내부의 문자열 비교로 흩뜨리지 않는다. `SVNPathIdentity`가 원문·비교 키·표시 경로를 소유하고, `SVNWorkingCopySnapshot`이 상태 축약과 경로 매핑을 담당한다. `SVNStatusEntry`는 상태 의미를 판정하는 계산 속성을 제공한다. `ChangesView`, `ProjectStore`, 커밋, 복구 서비스가 같은 판정을 재사용한다.

## 테스트

- `revision=-1`인 `missing`이 추가 예약 누락으로 분류되는지 검증한다.
- 일반 리비전의 `missing`은 추가 예약 누락으로 분류되지 않는지 검증한다.
- NFD 새 경로가 NFC 기존 상위 경로에 자동 매핑되는지 검증한다.
- NFC/NFD 정상 경로가 둘 이상이면 충돌로 차단되는지 검증한다.
- 중복 추가 예약 트리가 최상위 충돌 하나로 축약되는지 검증한다.
- 새로고침 후 추가 예약 누락 경로가 선택 집합에서 제거되는지 검증한다.
- 충돌이 있으면 커밋 전 어떤 add/delete 명령도 실행되지 않는지 검증한다.
- 커밋 실패 시 이번 호출에서 만든 예약만 revert하는지 검증한다.
- 복구가 실제 수정·추가·삭제만 새 작업 복사본에 이관하고 원본을 보존하는지 검증한다.
- 화면 소스 회귀 테스트로 세 상태의 한국어 문구와 선택 제한이 유지되는지 검증한다.
- 전체 `swift test`를 실행한다.
