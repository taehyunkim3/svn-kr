# SVN Mac 레이아웃 구조

## 목표

콘텐츠 양과 화면 상태가 달라져도 좌우 패널의 시작점, 높이, 배경 범위가 바뀌지 않아야 한다.
레이아웃 문제를 개별 화면의 `.frame` 추가로 해결하지 않고 크기 소유자를 고정한다.

## 크기 소유권

| 영역 | 크기 소유자 | 규칙 |
| --- | --- | --- |
| 앱 창 | `AppLayout`과 `SVNMacApp` | 최소/기본 크기를 한곳에서 관리한다. |
| 프로젝트 사이드바 | `AppLayout`과 `ContentView` | 최소/이상/최대 너비를 모두 지정한다. |
| 작업 화면 좌우 분할 | `WorkspaceSplitView` | 전체 높이와 좌우 최소 너비를 함께 결정한다. |
| 기록 상세 파일 목록 | `AppLayout.historyChangedFilesHeight` | 상태와 파일 개수에 관계없이 같은 높이를 사용한다. |
| 기록 상세 diff | `HistoryRevisionDiffView` | 파일 목록 아래의 남은 높이를 모두 사용한다. |
| 시트 | `AppLayout`과 `appSheetFrame` | 최소 크기를 한곳에서 관리하고 루트 컨테이너가 시트 전체 크기를 채운다. |

## 구조 불변식

1. `TabView` 아래의 변경/기록 화면은 모두 `WorkspaceSplitView`를 사용한다. 파일 탐색 화면은 단일 전체 너비 목록을 유지한다.
2. 작업 화면 내부에는 사용자 요구가 없는 중첩 SplitView를 만들지 않는다.
3. 커밋 미선택, 파일 미선택, 로딩, 결과, 오류 상태는 같은 패널 컨테이너 안에서 전환한다.
4. `idealWidth`와 `idealHeight`는 고정 크기가 아니므로 정렬 보장 용도로 사용하지 않는다.
5. 패널 배경은 전체 크기 frame 뒤에 적용한다.
6. 새 레이아웃 숫자가 필요하면 `AppLayout`에 의미 있는 이름으로 추가하고 크기 불변식 테스트도 갱신한다.
7. 시트의 빈 상태는 `List`나 본문 컨테이너를 교체하지 않고 그 컨테이너의 `overlay`로 표시한다. `frame(minWidth:minHeight:)`만 루트에 적용해 작은 콘텐츠 묶음이 가운데 정렬되게 두지 않는다.

## 확인 조합

레이아웃 변경 후 아래 조합을 확인한다.

- 창 크기: 최소 `1120×700`, 기본 `1280×780`, 기본보다 큰 창
- 탭: 변경 사항, 커밋 기록
- 변경 상태: 변경 파일 없음, 파일 1개, 파일 다수, 무시된 파일 표시
- 기록 상태: 커밋 미선택, 파일 1개, 파일 100개 이상, 파일 미선택, 로딩, diff 표시
- 콘텐츠: 긴 저장소 경로, 긴 커밋 메시지, 가로로 긴 diff 행, 빈 diff
- 동작: 탭 전환, 창 확대/축소, 다른 프로젝트 선택, 커밋과 파일 연속 선택
- 시트: 잠금·무시 규칙·업데이트 미리보기·파일 기록의 빈 상태와 결과 상태에서 헤더와 푸터 위치 유지

자동 검증은 `Tests/SVNMacTests/AppLayoutTests.swift`에서 창과 패널 최소 크기의 합 및 크기 범위를 확인한다.
기능 회귀 검증은 저장소 루트에서 `swift test`를 실행한다.
